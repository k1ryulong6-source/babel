# 巴别塔改版设计稿（v0.3.1，主笔：Claude；已经 GPT 审稿两轮）

> 范围：①课程教学重做 ②课时播放器（往回翻页、复习）③UI 与动效 ④内容量扩充 ⑤做成安卓 App。
> 审稿记录与逐条回应见 `docs/reviews/REDESIGN-2026-11-26.md`（第一轮，gpt-6.1-sol）和 `docs/reviews/REDESIGN-2026-11-26-r2.md`（第二轮，gpt-6.2-sol）。
> v0.2 → v0.3：区分“走完”和“能独立用”并定义通过标准；课内时间重新分配；判题与反馈本地化；排课超量规则；复习按“知识点＋能力”去重；断点状态规则；试点课独立课号；离线与存档迁移的验收范围。
> v0.1 → v0.2 的主要变化：统一“屏”的口径；把新课和复习放进同一个每日 40 分钟预算；每屏必须有认知动作；复习改为统一队列加时间上限；首期只做 Android；执行顺序提前做安卓最小播放器和跨日验证。

## 0. 已确定的前提（用户已拍板）

- 每课 30–40 屏，**每一屏都要动脑**，不允许“只看不做”的屏。
- 练习从“认”到“用”分级，必须有产出题和间隔复习。
- 播放器能往回翻页、能复习。
- UI 有清晰的视觉重心和流畅动效。
- 最终形态是 **Android App**。
- 每天学习约 **40 分钟，包含新课和复习**，三门语言共用这一个预算。

## 1. 诊断

### 1.1 统一口径

- **教学屏**＝一个有学习目标、有作答动作的页面；提交后在原页展示反馈，**反馈不另计屏**。
- 另外记录：任务数、反馈次数、重试次数、实际用时。新版 30–40 屏按这个口径验收。
- 按此口径，现版 `es.2.5.1` 是 39 个进度项、49 次独立任务展示，其中可判分作答 28 次：词义回忆 12 + 选择 9 = 21 次，整句中译外只有 2 次，听写 1 次（v0.1 写的“77–91 屏”把每道题的反馈也算成了一屏，口径不一致，作废）。
- 基线和新版都并列记录：展示数、首次作答类型、无提示表达次数、跨日运用表现。

### 1.2 问题

0. **把“走完流程”当成“学会”**：现版走到小结就标记 `done`，并把本课内容加入调度；没有区分首次作答、提示后修正和跨日独立运用。即使加大作答量，完成状态仍会高估学习结果。新版分开两个状态：**流程完成**、**能独立使用**（判定见第 2 节“精熟检查”）。
1. **没有能力目标**：课程围绕“每课 2 个重点、12–15 个词”组织，没先定义“学完能独立做什么”，于是覆盖很多、独立运用很少，新词和语法争抢同一段时间。
2. **练习以“认”为主**：选择题和回忆小测为主；会选对不代表能说出来、写出来。
3. **练得太集中、太即时**：刚看完就考，靠短时记忆。
4. **输入缺少可理解的上下文和能区分角色的反例**：每课只有 4–6 句情境。问题不只是句数少，而是缺少能暴露误解的对比；加长文本本身不解决问题。例如用 `Doy la llave a Marta` 分别问“替换钥匙”（`La doy a Marta`）和“替换 Marta”（`Le doy la llave`），再对照 `Veo a Marta → La veo`。
5. **反馈质量不均、产出覆盖不足**：现版已有题目解析、写作 AI 批改 / 范文对照、错题重做，但解析覆盖不全，自由产出太少，反馈后不要求修正。
6. **复习没有形成闭环**：现版已有重点笔记和按 FSRS 调整间隔的重点复习，但课前回顾来源单一，重点复习只在少量 drill 中轮换；各种复习入口互不去重，也没有和每日时间预算挂钩。
7. **现有讲解有教错的地方**：例如 `es.2.5.2` 写 “Le regalé un libro a Juan……le 不能省”，实际上 `Regalé un libro a Juan` 也成立（后置间接宾语时 le 的重复通常可选）。同一讲解还把 `dar` 归为“间接宾语动词”，让学习者靠中文能否加“什么”来选代词；但同一个动词可以同时带两种宾语，判断依据应是“被替换的成分是什么角色”，不是动词类别。批量改写前需要一轮内容纠错。
8. **播放器不能往回翻**。

## 2. 教学原则

| 原则 | 在课里怎么体现 |
|---|---|
| 每屏一个认知动作 | 每屏标明动作类型：理解意思 / 辨别角色 / 回忆形式 / 改写 / 表达 / 修订。点击、播放、点“下一步”只是操作，不算学习动作 |
| 检索练习 | 先凭记忆答，再看答案；选择题可用于检查意义理解，但不能代替产出 |
| 间隔与交错 | 课内把同一结构隔开练；跨日用**不同语境**再检索，课内重复不替代跨日复习 |
| 先输入、再注意、后讲解 | 先听读含目标结构的短文并回答意思题，再用 2–3 组对比例句判断具体差异，最后讲规则 |
| 样例渐隐 | 完整分析 → 补最后一步 → 独立完成 |
| 推动式输出 + 可执行的反馈 | 反馈指出可观察的错误（“这里替换的是接受者，所以用 le”），**随后要求学习者修正** |
| 精熟检查 | 出口题只表示当堂表现；次日和一周后用新语境再查，才算掌握（标准见下） |

**“能独立使用”的判定**：每课把能力拆成 2–3 个证据项（lo/la/le 这课是：指代与角色、代词形式、位置与否定）。出口题记录当堂首次表现；次日和一周后各用 3 道新语境短题覆盖这几项，某项两次都**首次独立通过**才标记“跨日通过”。用过提示、看过答案、自查待确认、未到检验日期都分别记录，不算通过；某一项失手只复习这一项。有字幕时答对记为听读理解，纯听力证据另记。

数字类参数（目标结构出现次数、复现次数、短文长度）都是**试点参数**，由试点数据校准，不作为通用处方。

**三门语言共用播放器和题型组件，但各有教学模板**：西语（A1–A2）侧重意义与形式的对应；英语托业课保留听读判断和限时策略；高阶日语侧重语体、改写与论证表达，不照搬初级“发现语法”的流程。

## 3. 新课时结构（36 屏、课内约 28 分钟，试点目标值）

每课先写三样东西，再分配屏数：**一条可观察的能力目标、先修条件、验收任务**；明确本课**不**讲什么（例如 lo/la/le 这课不讲复数、中性 lo、se lo、不定式位置）。

| 段落 | 屏数 | 目标用时 | 内容 |
|---|---:|---:|---|
| ① 开场旧知识检索 | 3 | 3 分 | 产出为主；只有实际命中到期任务、且有对应作答证据时才**抵扣当天复习** |
| ② 分段听读与意义判断 | 4 | 3 分 | 一篇短文分 4 屏呈现（西语试点约 80–120 词，以已学词为主），每屏一道意思题 |
| ③ 对比发现、讲解与检查 | 5 | 4 分 | 指代辨认 → 对比判断 → 角色区分 → 样例渐隐；讲解在答完后同屏展开 |
| ④ 从辨认到独立改写 | 9 | 5 分 | 受控产出（无选项填空、替换）→ 最小对比 → 独立改写、否定短答 |
| ⑤ 交错与延迟检索 | 6 | 4 分 | 插入旧知识、延迟词汇检索、新语境迁移、改错 |
| ⑥ 情境表达与修订 | 4 | 6 分 | 规划 → 写 3 条简短交际信息 → 在原输入框就地修订 → 一句单句迁移 |
| ⑦ 出口小测 | 5 | 3 分 | 2 道快判 + 3 道单句产出；先锁定整组首次作答，再按需回看反馈。给明确的人物、指代对象和表达目的，不给词库、句型和答案 |
| **合计** | **36** | **28 分** | |

时间分配说明：从输入段和受控练习各省 1 分钟，给最费时的表达与修订段。试点分别记录首答、键盘操作、重播、反馈和订正用时；28 分钟是整课估时，超出时允许保存断点。

新词不再单开一段，在输入和练习中学习、复现，不在“穿插”名下暗加时间。试点真正的新词先限 4–6 个，按实际复习成本再调。

**硬性规则**

1. 每个教学屏必须完成一个理解、判断、检索或表达任务才能推进；讲解、答案和解析在同屏展开。没有独立的纯阅读屏、过场屏；小结改为闭卷回忆或修正一句错误表述。
2. 题目分三类统计：辨认 / 受控产出 / 独立表达。连词成句算受控，不算自由产出。每课至少 6 次无词库的完整短句表达，以及一次“表达 → 反馈 → 修订”。
3. 讲解里的每个例句都有录音。
4. 同屏答错后修正；持续出错转入补教和复习队列，不无限追加页面。订正时间计入课内用时，超时就保存断点。
5. 判分保留语言变体（例如西语对男性人称直接宾语的 leísmo 不一律判错，逐题设置）。判分以**指代对象、交际意图、目标代词和位置**为准；整句重复名词而避开代词时，记“意思传达成功”，仍要补做目标结构。

**判题与反馈（本地完成，飞行模式可用）**：现版整句题只比对归一化后的答案列表，写作 AI 依赖外部接口。新版试点**逐题写明**：必达条件、可接受答案、常见错误及对应提示。例如答 `La doy la llave` 时先提示“这里替换的是收钥匙的人”，让学习者原地改一次。合理但答案表未覆盖的表达，对照范例自查，记为“待确认”；仍卡住时保存首次作答、给一条解释，并在后续安排新题。拼写提醒和本课语法错误分开记录。AI 批改只作增强，不是闭环的前提。

**对照方案**：两轮审稿各给了一套 lo / la / le 的 36 屏序列。以第二轮的“社团前台失物交接”版（见 `docs/reviews/REDESIGN-2026-11-26-r2.md`）为试点起点稿，它的时间分配和出口题设计与上表一致；第一轮版本作备选素材。

## 4. 每日 40 分钟预算与复习

### 4.1 预算

记账口径：**新学 25 分钟 + 复习 11 分钟 + 跨任务余量 4 分钟 = 40 分钟**（课内订正已含在课内估时里）。课内开场 3 分钟只有实际完成的到期题才从 11 分钟复习里扣；先修诊断算新课耗时。

- 三门语言、重点、词汇、错题、单元测验、欠下的课**共用一个余额**。排入下一项前先估成本，余额不足就停止排任务；移除现版“至少再排 8 屏”之类的强制下限。现版默认的工作日 45 分钟 / 休息日 90 分钟改为统一 40 分钟。

**排课规则**

1. 复习需求 ≤ 11 分钟：正常排；没排满的部分留给新课。
2. 复习需求 > 11 分钟（**用户已定：新课照常，每天一整课，不拆课、不设纯复习日**）：复习只做 11 分钟，先做近期的跨日检查和关键先修，其他到期项按逾期程度和预估耗时排序；没做完的顺延到第二天，排在队列前面。新课不受影响。
3. 测验日：先从任务池里留出测验时段（现版单元测验默认估时 18 分钟），再按 1、2 排。
4. 不设纯复习日。
5. 顺延的复习积压连续两周上涨：先减少每课正式进入复习的新词（见第 11 节第 6 条），再重新模拟。不靠少开新课来减负。

**负荷估算**（三语合计每天新学一课，每项后续复习 5 次，能力项每次 30–60 秒，词每次 12 秒）：

| 每天新增 | 复习耗时 | 再加 3 分钟错题 / 补教 |
|---|---|---|
| 1 个能力项 + 4–6 个词 | 6.5–11 分钟 | 9.5–14 分钟 |
| 2 个能力项 + 4–6 个词 | 9–16 分钟 | 12–19 分钟 |

还没算已有词卡的到期量和阶段测验。复习占到 12–19 分钟时，新学只剩 17–24 分钟。所以“每天守住 40 分钟”只证明停止派题及时，**积压是否累积**要单独验收（见第 9 节的 60 天模拟）。

### 4.2 统一复习队列

“没懂”、开场检索、错题、重点复习、复习本课全部汇入**一个队列**，按“**语言 + 知识点 + 要求的能力**”合并（做对一道 lo/la 选择题不能抵掉同一知识点的表达任务）。一次符合要求的**首次独立作答**抵扣一次；提示后重做只记为订正；FSRS 对同一到期任务只更新一次。

- 调度沿用现有的自适应（FSRS）算法，不用固定的 1/3/7/15/30 天；连续答错的项目转入补教。
- 复习题优先**未见过的新情境**；题量不足时允许间隔复用合格旧题；不从未学过的课取题。
- “复习本课”（课后可选，约 5 分钟）：闭卷检索 2–3 题 → 必要时展开解释 → 修正，完成后抵扣当天对应的到期任务。
- “时间紧”的选项（只在你当天主动选择时生效，系统不会因为复习多而自动触发）：**暂停续学**（在一小段结束后保存断点）或**今天只复习**。续学仍从原断点走完整条路径。首期不做删屏的“精练版”，避免正式课被减到 30 屏以下。

## 5. 课时播放器

1. **往回翻页**，两个入口：
   - **回看**：显示首次作答和解析。
   - **再练**：隐藏答案重新作答，首次成绩保留不变，练习结果单独记录（防刷分靠分开记录，不靠禁止重答）。
   - 回翻后一键回到学习断点。
   - 再练必须先作答才能揭示答案；回看可以直接离开。
2. **作答记录**：保存每屏答案、草稿、提示使用和反馈。新增稳定的屏 / 题 / 知识点 ID 和课程版本映射，课程重排后旧进度不会指错。
3. **断点状态规则**：分别保存“**正式学习断点**”“**当前浏览位置**”和作答记录。
   - 例：第 24 屏打了一半，回第 18 屏再练，此时 Android 回收了进程。重启默认恢复到第 24 屏及其草稿；第 18 屏的再练可从记录里继续。
   - 每屏保存三种状态：输入中、已提交待反馈、反馈待订正。
   - 重复点提交或重启恢复时，首次成绩、用时、复习扣账**各只记一次**。
4. **课内目录**：可展开的段落列表（不靠点击七个窄进度段），点一节可跳回已学过的部分。
5. **“没懂”标记**：任意教学屏都能点，并选原因（词义 / 规则 / 句意 / 音频）；点完先给针对性帮助，再进复习队列。

## 6. UI 与动效

- **视觉重心随任务切换**：听力屏突出播放和问题；改写屏突出原句和输入框；反馈屏突出用户答案和关键修正。正文保持可读，不强制“目标语永远最大”。
- **主按钮**位于键盘和系统安全区上方，保留次要的“上一屏 / 目录”入口；点击区域以 48dp 为目标。
- **统一设计变量**：字号阶梯、间距阶梯、颜色语义（正确 / 错误 / 提示 / 强调），三门语言共用骨架，只换主题色和字体。
- **动效**：前进 / 回退用短距离位移加淡入；反馈用文字 + 图标 + 颜色共同表达，展开解析时题目位置不跳动；段落标题放在下一任务页内，不做独立过场；“减少动态效果”开启时关闭位移、缩放和晃动。时长参数（如 200ms 左右）在原型里实测再定。流畅首先靠状态连续、不跳动、响应及时，而不是动画数量。
- **做法**：
  1. **在最小 APK 阶段**就做一条交互流程：输入 → 提交 → 同屏反馈 → 原地改写 → 回翻 → 续学。
  2. 在 360dp 宽、系统大字体、键盘展开、长解析**四者同时出现**时验收：题干至少保留一行必要语境；当前输入框和主按钮可达；长解析按需展开；输入焦点和光标不跳。
  3. 真机检查中文输入法组字、系统返回手势、减少动态效果；快速连点只提交一次；反馈出现后可立即继续操作。
  4. 交互通过后，再比较 2–3 个视觉风格，你挑一个推广到全应用。

## 7. 内容

| 项目 | 做法 |
|---|---|
| 优先级 | 先做**当前学习位置的一课及它的后续复习题**，再覆盖相邻课；不先追求全库数量 |
| 课型 | 分别制定“讲解课”和“综合阅读课”模板（现有 264 课里含 44 节单元阅读），阅读课同样要有 30–40 个有意义的任务 |
| 题库 | 先补试点课的题，并给每题加：知识点、能力层级、题型、可接受答案、预计耗时；同步更新 `docs/QUESTION_BANK.md`（现有 44 个单元的 bank 均无题） |
| 词库例句 | 先补学习路径上要用的词，保证展示不同用法，并进入检索任务 |
| 内容纠错 | 批量改写前，先审一轮现有讲解里的语法错误（如第 1.2 节第 7 条） |

## 8. 安卓 App

- **首期只做 Android APK**（Capacitor 套壳，沿用网页代码），是否上架商店另定。不做 iOS，不用 React Native / Flutter 重写。
- **局部拆分，不先全面重构**：先拆出播放器状态、判题、复习调度、存储、音频这几个模块，尽早跑通最小 APK；其余代码渐进拆分。
- **离线交付范围**：
  - 最小 APK 随包带试点课、题目、录音、复习题和本地反馈，**飞行模式下首次启动也能走完整条流程**。
  - 全库录音（仓库 `audio/` 源文件约 295 MiB，APK 与安装后占用待实测）之后按语言或单元装包：安装前显示大小；断网恢复后补齐缺失文件，校验成功才标记“可离线”。
  - 每日提醒和后台播放排在核心流程之后（后台播放受系统限制）。
- **返回键规则**：先关键盘 / 弹层，再返回页面；课内“上一屏”由播放器按钮处理。
- **存档迁移**（现版逐份覆盖记录，中途失败会留下一半）：保留旧 JSON 格式读取；先校验版本和内容，预览将迁入的课时和复习量，再通过系统文件选择器导入；迁移映射校验成功后**一次提交**。验收至少覆盖：导入中途中断、同一存档重复导入、旧课位置无法对应、APK 升级后断点恢复。

## 9. 执行顺序

1. **统一口径**：屏、能力目标、时间预算的定义写进规范。
2. **局部拆分 + 安卓最小播放器**跑通（真机），同时做第 6 节的交互流程验收。
3. 实现回翻（回看 / 再练）、断点状态、作答与草稿保存、本地判题与修订、统一复习队列和 40 分钟预算。
4. 做试点课（lo / la / le，独立课号）及其次日、一周后的复习题。
5. **真机试学 + 延迟检查**：记录首次正确率、提示使用、修订、各段用时、中断恢复；次日和一周后按第 2 节标准判定“跨日通过”。技术验收含飞行模式、锁屏恢复、进程重启、中文 / 西语键盘切换、存档导入。
   - 另做排课模拟至少 60 天：以已有学习记录为起点，跑连续缺学、较高错答率、三语同时到期等情形，报告**逾期分钟、最老逾期天数、跨日检查兑现率、新课完成率**。
6. 定稿写课规范和写课工具（见第 7 节“规范与工具同步”），先纠错现有讲解。
7. 按当前学习进度扩展内容；UI 原型 → 播放器改版 → 全应用改版。

## 10. 合作方式（Claude × GPT）

## 11. 需要用户决定的事

1. ~~复习多的日子，新课怎么推进？~~ **已定（2026-11-26）：一切照常。**每天照常学一整课，不拆成两天，也不留纯复习日；超出 11 分钟的复习顺延到第二天。代价是复习多的那段时间积压会增加，靠第 9 节的 60 天模拟盯着，必要时先减新词量。
2. **独立产出的主要方式？** 建议首期以文字短句为主、口头作答可选；若更重视开口，需要先做录音、回听和口语反馈，并相应压缩其他任务。
3. **旧课程重做范围？** 建议先重做正在学和紧接着要学的课，再逐步迁移；若选全量重做，应暂缓新学期和全词库例句。
4. **安卓首发方式？** 建议先交付可安装 APK，上架商店以后再定。
5. **复习拥挤时，优先保当前主课，还是保三门语言每周都有练习？** 建议先保当前主课进度，同时把另外两门最久没练的项目优先排回队列。
6. **持续超载时减什么？** 因为第 1 条定了每天照常开新课，“少开新课”已排除。建议减少正式进入复习的新词（课文里低频、只需读懂的词保留点击释义）。
