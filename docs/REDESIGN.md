# 巴别塔改版设计稿（v0.1，主笔：Claude；待 GPT 审稿）

> 范围：①课程教学重做 ②课时播放器（往回翻页、复习）③UI 与动效 ④内容量扩充 ⑤做成真正的 App。
> 审稿人请先读第 9 节，再逐节提意见。

## 1. 诊断：为什么“四十页、不用四十分钟、学完像没学”

用浏览器走课测试统计第二学期的课（每课 77–91 屏）：

| 屏的类型 | 每课屏数 | 占比 | 学习者实际在做什么 |
|---|---|---|---|
| 新词卡 | 12 | 15% | 看一眼释义和例句 |
| 回忆小测 | 24 | 30% | 刚看完的词马上认一遍（四选一） |
| 重点讲解 | 6（2 个重点 × 3 屏） | 7% | 读几行要点 |
| 情境 / 跟读 / 小结 | 3 | 4% | 读 4–6 句对话，跟读 1 句 |
| 练习（含重点练习） | 30–35 | 40% | 七成是选择题，中译外、连词成句各 2 题 |

问题不在页数，而在**每一屏要求的思考太少**：

1. **讲解太薄，而且是“告诉”不是“教会”**：一个重点被压成几条要点，读完就过，学习者没有自己推理、发现、出错再纠正的过程。
2. **练习以“认”为主，不是“用”**：选择题和回忆小测只考辨认，答对不代表能说出来、写出来。
3. **练得太集中、太即时**：词刚看完就考，重点刚讲完就练，靠的是短时记忆，第二天就忘（集中练习的典型效果）。
4. **输入量太少**：每课只有 4–6 句情境对话，目标结构在真实语境里只出现两三次，形成不了语感。
5. **几乎没有产出和反馈**：写作和中译外很少，错了只给标准答案，不分析“为什么会这样错”。
6. **复习只是走过场**：课前回顾只出上一课重点的最后一道题；以前单元的内容在后面的课里基本不再出现。
7. **播放器不能往回翻**：没看懂也回不去，只能硬着头皮往下点。

## 2. 教学原则（新课程的设计依据）

| 原则 | 在课里怎么体现 |
|---|---|
| 检索练习（retrieval practice） | 先让学习者凭记忆说出 / 写出，再看答案；每屏都要有动作 |
| 间隔与交错（spacing / interleaving） | 新词、重点在本课分散出现 3 次以上；课前检索混入 1 课前、3 课前、1 单元前的内容 |
| 先输入、再注意、后讲解（input → noticing → rule） | 先读 / 听一段含目标结构 8–12 次的短文，回答意思问题，再引导“发现规律”，最后才讲规则 |
| 生成效应（generation） | 规则讲解前先让学习者猜、先尝试，再揭示 |
| 样例渐隐（worked example → fading） | 先看完整的分析步骤，再做“补一步”的题，最后完全独立做 |
| 推动式输出（pushed output）+ 有针对性的反馈 | 每课至少一个产出任务；每个干扰项都有“你为什么会选这个”的解析 |
| 精熟检查（mastery check） | 课末出口小测全部是产出题，成绩决定这个重点多快再复习 |

## 3. 新课时结构（每课约 30–40 屏、25–35 分钟，但每屏都要动脑）

| 段落 | 时长 | 内容 | 题型 |
|---|---|---|---|
| ① 开场检索 | 3–4 分 | 6 题：上一课 2 题、3 课前 2 题、上一单元 2 题 | 产出为主（填空、中译外、听写） |
| ② 输入 | 5 分 | 一段 150–250 词（日语 400–600 字）的对话或短文，有录音，目标结构出现 8–12 次；先答 3 道意思题 | 理解题 |
| ③ 发现 | 3 分 | 从短文里挑出 4–6 个含目标结构的句子，问“这些句子有什么共同点 / 为什么这里用 A 不用 B”，先让学习者猜 | 选择 / 填空，答完再揭示 |
| ④ 讲解 | 5 分 | 规则 + 2 个完整样例分析 + 和中文对比 + 常错；**每屏讲完马上问一个小问题**（先预测、再揭示） | 讲解屏与小题交替 |
| ⑤ 分级练习 | 8 分 | 辨认 → 半控制产出（改写、填空、变形）→ 自由产出；交错复习本课新词 | 每个干扰项都有针对性解析 |
| ⑥ 新词 | 穿插 | 词从输入短文里来，不再孤立地列 12 张卡；本课内分散复现 3 次 | 词义匹配、用词造句 |
| ⑦ 输出任务 | 4 分 | 用本课重点写 3–5 句或录一段话；有 AI 时批改，没有时给范文 + 自查清单 | 写作 / 口语 |
| ⑧ 出口小测 | 3 分 | 5 道完全不给提示的产出题 | 结果写入重点笔记，决定复习间隔 |

**硬性规则**：连续两屏都只是“读”不允许；每课产出题不少于练习总数的一半；讲解里的每个例句都有录音。

## 4. 课时播放器的新功能

1. **往回翻页**：可以回到任意一屏重看。已答过的题回看时只显示自己的作答和解析，不能重新答（不刷分）；讲解屏、输入短文可以反复看。
2. **课内目录**：顶部进度条按段落分节（检索 / 输入 / 发现 / 讲解 / 练习 / 输出 / 小测），点一节可跳回去复看已学过的部分。
3. **“没懂”标记**：任何讲解屏都能点“没懂”，这一屏会进复习，并在下一课的开场检索里优先出题。
4. **复习**：
   - 课后“复习本课”：只看讲解屏 + 重做出口小测，5 分钟。
   - 间隔复习：重点笔记按 1、3、7、15、30 天复习，每次从题库抽**新的**产出题（用到单元题库 `bank`），不再只重复同一道题。
   - 单元复习：单元题库练习（已做好）+ 单元测验。
5. **可调节奏**：设置里可以选“标准 / 精练”，精练模式跳过输入短文的意思题和部分分级练习，适合时间紧的日子。

## 5. UI 与动效方向

- **视觉重心**：每屏只有一个主角。目标语句子最大、最醒目，中文和说明降级为次要层级；每屏只有一个主按钮，固定在拇指能碰到的位置。
- **统一设计变量**：字号阶梯、间距阶梯、颜色语义（正确 / 错误 / 提示 / 强调）全部用变量，三门语言共用一套骨架，只换主题色和字体。
- **动效**：
  - 屏与屏之间：向前翻页横向滑入（约 220ms，ease-out），往回翻页反向滑入。
  - 答题反馈：正确时选项轻微放大并变色，错误时左右轻晃，解析从下方展开。
  - 进度条平滑增长；段落切换时有段落标题的过场（约 600ms）。
  - 尊重系统的“减少动态效果”设置，开启时只保留淡入淡出。
- **做法**：先做播放器一屏的 2–3 个视觉方案原型（可交互的网页），你挑一个，再推广到全应用。

## 6. 内容量扩充

| 项目 | 现状 | 目标 | 生产方式 |
|---|---|---|---|
| 每课输入短文 | 4–6 句情境 | 每课 1 篇（150–250 词 / 400–600 字） | 主笔写，对方审 |
| 单元题库 | 0 | 每单元 60 题（44 单元约 2600 题） | 见 `docs/QUESTION_BANK.md` |
| 词库例句 | 英 2 句 / 西日 1 句 | 每词 3 句 | 见 `docs/LEXICON.md` |
| 新学期 | 英 3 / 西 3 / 日 3 未写 | 按新结构写 | 先做试点课，验证有效再铺开 |

所有生成内容都过校验脚本（`check_curriculum.py`、`bank_merge.py`、`lexicon_merge.py`），再抽查质量。

## 7. 做成真正的 App

现在是一个约 960KB 的单文件网页，打包成 PWA。建议分两步：

1. **拆分代码**：把 `index.html` 拆成模块（播放器、排课、词库、复习、各页面），用构建工具打包。这是后面一切改动的基础，也让 UI 重做更容易。
2. **套原生外壳（推荐 Capacitor）**：沿用现有网页代码，生成真正的 Android / iOS 应用，获得：
   - 本地通知（每日学习提醒）
   - 录音文件存到手机文件系统（现在三门语言的录音约 280MB，网页缓存容易被系统清掉）
   - 后台下载、更稳定的音频播放、系统返回手势
   - 可以装 APK 或上架应用商店

不建议现在用 React Native / Flutter 重写：工作量大，而且会和课程、UI 重做同时进行，风险太高。等内容和交互稳定后，如果性能确实不够，再考虑重写。

## 8. 执行顺序

1. **试点课**：选一课（建议 `es.2.5.1` 或 `en.2.5.1`）按第 3 节的结构重做，同时实现播放器的往回翻页、课内目录、“没懂”标记。你实际学一遍，确认效果。
2. **定稿课程模板**：根据试点反馈改结构，写成新的写课规范（替换 `docs/HANDOFF.md` 第 4 节）。
3. **UI 原型 → 播放器改版 → 全应用改版**（含动效）。
4. **批量重做 / 扩充内容**：先第二学期，再第一学期，再新学期；题库和例句并行。
5. **拆分代码 → Capacitor App**。
