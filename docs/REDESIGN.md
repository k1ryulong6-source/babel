# 巴别塔改版设计稿（v0.2，主笔：Claude；已经 GPT 审稿一轮）

> 范围：①课程教学重做 ②课时播放器（往回翻页、复习）③UI 与动效 ④内容量扩充 ⑤做成安卓 App。
> 审稿记录与逐条回应见 `docs/reviews/REDESIGN-2026-11-26.md`。v0.1 → v0.2 的主要变化：统一“屏”的口径；把新课和复习放进同一个每日 40 分钟预算；每屏必须有认知动作；复习改为统一队列加时间上限；首期只做 Android；执行顺序提前做安卓最小播放器和跨日验证。

## 0. 已确定的前提（用户已拍板）

- 每课 30–40 屏，**每一屏都要动脑**，不允许“只看不做”的屏。
- 练习从“认”到“用”分级，必须有产出题和间隔复习。
- 播放器能往回翻页、能复习。
- UI 有清晰的视觉重心和流畅动效。
- 最终形态是 **Android App**。
- 每天学习约 **40 分钟，包含新课和复习**，三门语言共用这一个预算。

## 1. 诊断

### 1.1 统一口径

- **教学屏**＝一个有学习目标、有作答动作的页面；提交后在原页展示反馈，**反馈不另计屏**。
- 另外记录：任务数、反馈次数、重试次数、实际用时。新版 30–40 屏按这个口径验收。
- 按此口径，现版 `es.2.5.1` 是 39 个进度项、49 次独立任务展示（v0.1 写的“77–91 屏”把每道题的反馈也算成了一屏，口径不一致，作废）。

### 1.2 问题

1. **没有能力目标**：课程围绕“每课 2 个重点、12–15 个词”组织，没先定义“学完能独立做什么”，于是覆盖很多、独立运用很少，新词和语法争抢同一段时间。
2. **练习以“认”为主**：选择题和回忆小测为主；会选对不代表能说出来、写出来。
3. **练得太集中、太即时**：刚看完就考，靠短时记忆。
4. **输入量太少**：每课 4–6 句情境，目标结构在语境里只出现两三次。
5. **反馈质量不均、产出覆盖不足**：现版已有题目解析、写作 AI 批改 / 范文对照、错题重做，但解析覆盖不全，自由产出太少，反馈后不要求修正。
6. **复习没有形成闭环**：现版已有重点笔记和按 FSRS 调整间隔的重点复习，但课前回顾来源单一，重点复习只在少量 drill 中轮换；各种复习入口互不去重，也没有和每日时间预算挂钩。
7. **现有讲解有教错的地方**：例如 `es.2.5.2` 写 “Le regalé un libro a Juan……le 不能省”，实际上 `Regalé un libro a Juan` 也成立（后置间接宾语时 le 的重复通常可选）。批量改写前需要一轮内容纠错。
8. **播放器不能往回翻**。

## 2. 教学原则

| 原则 | 在课里怎么体现 |
|---|---|
| 每屏一个认知动作 | 每屏标明动作类型：理解意思 / 辨别角色 / 回忆形式 / 改写 / 表达 / 修订。点击、播放、点“下一步”只是操作，不算学习动作 |
| 检索练习 | 先凭记忆答，再看答案；选择题可用于检查意义理解，但不能代替产出 |
| 间隔与交错 | 课内把同一结构隔开练；跨日用**不同语境**再检索，课内重复不替代跨日复习 |
| 先输入、再注意、后讲解 | 先听读含目标结构的短文并回答意思题，再用 2–3 组对比例句判断具体差异，最后讲规则 |
| 样例渐隐 | 完整分析 → 补最后一步 → 独立完成 |
| 推动式输出 + 可执行的反馈 | 反馈指出可观察的错误（“这里替换的是接受者，所以用 le”），**随后要求学习者修正** |
| 精熟检查 | 出口题只表示当堂表现；次日和一周后用新语境再查，才算掌握 |

数字类参数（目标结构出现次数、复现次数、短文长度）都是**试点参数**，由试点数据校准，不作为通用处方。

**三门语言共用播放器和题型组件，但各有教学模板**：西语（A1–A2）侧重意义与形式的对应；英语托业课保留听读判断和限时策略；高阶日语侧重语体、改写与论证表达，不照搬初级“发现语法”的流程。

## 3. 新课时结构（36 屏、课内约 28 分钟，试点目标值）

每课先写三样东西，再分配屏数：**一条可观察的能力目标、先修条件、验收任务**；明确本课**不**讲什么（例如 lo/la/le 这课不讲复数、中性 lo、se lo、不定式位置）。

| 段落 | 屏数 | 目标用时 | 内容 |
|---|---:|---:|---|
| ① 开场旧知识检索 | 3 | 3 分 | 产出为主；来自统一复习队列，**抵扣当天到期复习** |
| ② 分段听读与意义判断 | 4 | 4 分 | 一篇短文分 4 屏呈现（西语试点约 80–120 词，以已学词为主），每屏一道意思题 |
| ③ 对比发现、讲解与检查 | 5 | 4 分 | 指代辨认 → 对比判断 → 角色区分 → 样例渐隐；讲解在答完后同屏展开 |
| ④ 从辨认到独立改写 | 9 | 6 分 | 受控产出（无选项填空、替换）→ 最小对比 → 独立改写、否定短答 |
| ⑤ 交错与延迟检索 | 6 | 4 分 | 插入旧知识、延迟词汇检索、新语境迁移、改错 |
| ⑥ 情境表达与修订 | 4 | 4 分 | 规划 → 写 3 条简短交际信息 → 诊断自己的错误 → 修订并迁移；4 分钟含修订 |
| ⑦ 出口小测 | 5 | 3 分 | 不给词库、句型和答案，但给明确的人物、指代对象和表达目的 |
| **合计** | **36** | **28 分** | |

新词不再单开一段，在输入和练习中学习、复现，不在“穿插”名下暗加时间。试点真正的新词先限 4–6 个，按实际复习成本再调。

**硬性规则**

1. 每个教学屏必须完成一个理解、判断、检索或表达任务才能推进；讲解、答案和解析在同屏展开。没有独立的纯阅读屏、过场屏；小结改为闭卷回忆或修正一句错误表述。
2. 题目分三类统计：辨认 / 受控产出 / 独立表达。连词成句算受控，不算自由产出。每课至少 6 次无词库的完整短句表达，以及一次“表达 → 反馈 → 修订”。
3. 讲解里的每个例句都有录音。
4. 同屏答错后修正；持续出错转入补教和复习队列，不无限追加页面。订正时间计入课内用时，超时就保存断点。
5. 判分保留语言变体（例如西语对男性人称直接宾语的 leísmo 不一律判错）。

**对照方案**：GPT 用 lo / la / le 写的 36 屏完整序列见审稿记录，作为试点课 `es.2.5.x` 的起点稿。

## 4. 每日 40 分钟预算与复习

### 4.1 预算

默认分配：**课内 28 分钟 + 课外到期复习 8 分钟 + 订正与操作余量 4 分钟 = 40 分钟**。课内已有 3 分钟旧知识检索，所以实际约 25 分钟新学、11 分钟旧知识。

- 三门语言、重点、词汇、错题、单元测验、欠下的课**共用一个余额**。排入下一项前先估成本，余额不足就停止排任务；移除现版“至少再排 8 屏”之类的强制下限。现版默认的工作日 45 分钟 / 休息日 90 分钟改为统一 40 分钟。
- 复习超量时**减少新学**：一课可以跨两天完成（断点保存），或安排复习日（见第 10 节待决）。
- 负荷估算（假设每天 2 个重点、12 个词、每项复习 5 次）：重点约 5–10 分钟 / 天，词汇约 12 分钟 / 天，合计 17–22 分钟，还没算错题和测验。这说明不能承诺“每天一整课 + 全部复习”，必须靠上限和准入控制。

### 4.2 统一复习队列

“没懂”、开场检索、错题、重点复习、复习本课全部汇入**一个队列**，同一知识点当天合并处理，完成一个入口就抵扣其他入口的同项任务。

- 调度沿用现有的自适应（FSRS）算法，不用固定的 1/3/7/15/30 天；连续答错的项目转入补教。
- 复习题优先**未见过的新情境**；题量不足时允许间隔复用合格旧题；不从未学过的课取题。
- “复习本课”（课后可选，约 5 分钟）：闭卷检索 2–3 题 → 必要时展开解释 → 修正，完成后抵扣当天对应的到期任务。
- “时间紧”的选项：今天只复习，或在一小段结束后保存断点；若做精练版，只减少同构练习，**保留意义理解、关键对比、独立产出和出口检查**。

## 5. 课时播放器

1. **往回翻页**，两个入口：
   - **回看**：显示首次作答和解析。
   - **再练**：隐藏答案重新作答，首次成绩保留不变，练习结果单独记录（防刷分靠分开记录，不靠禁止重答）。
   - 回翻后一键回到学习断点。
2. **作答记录**：保存每屏答案、草稿、提示使用和反馈。新增稳定的屏 / 题 / 知识点 ID 和课程版本映射，课程重排后旧进度不会指错。
3. **课内目录**：可展开的段落列表（不靠点击七个窄进度段），点一节可跳回已学过的部分。
4. **“没懂”标记**：任意教学屏都能点，并选原因（词义 / 规则 / 句意 / 音频）；点完先给针对性帮助，再进复习队列。

## 6. UI 与动效

- **视觉重心随任务切换**：听力屏突出播放和问题；改写屏突出原句和输入框；反馈屏突出用户答案和关键修正。正文保持可读，不强制“目标语永远最大”。
- **主按钮**位于键盘和系统安全区上方，保留次要的“上一屏 / 目录”入口；点击区域以 48dp 为目标。
- **统一设计变量**：字号阶梯、间距阶梯、颜色语义（正确 / 错误 / 提示 / 强调），三门语言共用骨架，只换主题色和字体。
- **动效**：前进 / 回退用短距离位移加淡入；反馈用文字 + 图标 + 颜色共同表达，展开解析时题目位置不跳动；段落标题放在下一任务页内，不做独立过场；“减少动态效果”开启时关闭位移、缩放和晃动。时长参数（如 200ms 左右）在原型里实测再定。流畅首先靠状态连续、不跳动、响应及时，而不是动画数量。
- **做法**：先做一套可交互原型，覆盖理解题、输入题、反馈页三种屏，在 360dp 宽、键盘展开、大字号、长解析四种状态下验证；再比较 2–3 个视觉风格，你挑一个推广。

## 7. 内容

| 项目 | 做法 |
|---|---|
| 优先级 | 先做**当前学习位置的一课及它的后续复习题**，再覆盖相邻课；不先追求全库数量 |
| 课型 | 分别制定“讲解课”和“综合阅读课”模板（现有 264 课里含 44 节单元阅读），阅读课同样要有 30–40 个有意义的任务 |
| 题库 | 先补试点课的题，并给每题加：知识点、能力层级、题型、可接受答案、预计耗时；同步更新 `docs/QUESTION_BANK.md`（现有 44 个单元的 bank 均无题） |
| 词库例句 | 先补学习路径上要用的词，保证展示不同用法，并进入检索任务 |
| 内容纠错 | 批量改写前，先审一轮现有讲解里的语法错误（如第 1.2 节第 7 条） |
| 校验 | 现有脚本（`check_curriculum.py`、`bank_merge.py`、`lexicon_merge.py`）只查格式和引用。新增新版结构校验：按统一口径数屏、检查每屏动作、先修内容、知识点归属、答案与音频引用、预计时长、迁移映射。试点课所有题目、答案和反馈逐项人工审；批量阶段按错误风险抽查 |

## 8. 安卓 App

- **首期只做 Android APK**（Capacitor 套壳，沿用网页代码），是否上架商店另定。不做 iOS，不用 React Native / Flutter 重写。
- **局部拆分，不先全面重构**：先拆出播放器状态、判题、复习调度、存储、音频这几个模块，尽早跑通最小 APK；其余代码渐进拆分。
- 逐项落实，不假设套壳自动获得：本地音频包（约 280MB）与下载失败恢复、学习状态保存、离线启动、每日提醒通知；后台播放按需实现（受系统后台限制）。
- **返回键规则**：先关键盘 / 弹层，再返回页面；课内“上一屏”由播放器按钮处理。
- 迁移：复用现有存档导出 / 导入，把网页里的学习数据导进 App；课程版本变更时做进度迁移。

## 9. 执行顺序

1. **统一口径**：屏、能力目标、时间预算的定义写进规范。
2. **局部拆分 + 安卓最小播放器**跑通（真机）。
3. 实现回翻（回看 / 再练）、作答与草稿保存、判题与修订、统一复习队列和 40 分钟预算。
4. 做试点课（lo / la / le，`es.2.5.x`）及其后续复习题。
5. **真机试学 + 延迟检查**：记录首次正确率、提示使用、修订、各段用时、中断恢复；次日和一周后用新语境检查同一能力。技术验收含飞行模式、锁屏恢复、进程重启、中文 / 西语键盘切换。另用排课模拟跑至少 60 天，检查每天能否守住 40 分钟、积压是否持续增长。
6. 定稿写课规范（替换 `docs/HANDOFF.md` 第 4 节），先纠错现有讲解。
7. 按当前学习进度扩展内容；UI 原型 → 播放器改版 → 全应用改版。

## 10. 合作方式（Claude × GPT）

- 课程设计、UI 设计：一方主笔，另一方审稿；审稿意见写进 `docs/reviews/<主题>-<日期>.md`，主笔逐条回应（采纳 / 部分采纳 / 不采纳及理由）。
- 两方意见冲突时，列出分歧点交给用户决定。

## 11. 需要用户决定的事

1. **复习多的日子，新课怎么推进？** 建议允许一课跨两天完成；另一种是每周 4–5 天推新课、其余为复习日。两种都守 40 分钟。
2. **独立产出的主要方式？** 建议首期以文字短句为主、口头作答可选；若更重视开口，需要先做录音、回听和口语反馈，并相应压缩其他任务。
3. **旧课程重做范围？** 建议先重做正在学和紧接着要学的课，再逐步迁移；若选全量重做，应暂缓新学期和全词库例句。
4. **安卓首发方式？** 建议先交付可安装 APK，上架商店以后再定。
